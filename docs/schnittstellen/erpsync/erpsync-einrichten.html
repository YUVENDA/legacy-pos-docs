ERPSync einrichten

Letzte Änderung 06.11.2026 · Version 3 · Seiten-ID 769

Der Dienst ALVARAErpSync gleicht die Kasseninstallation mit der ERP-Cloud ab. Diese Seite beschreibt, wie der Dienst als Windows-Dienst registriert wird und wie Sie ihn in einem Netz mit Proxy so konfigurieren, dass er die ERP-Cloud erreicht.

Voraussetzungen

  • Der ERPSync ist auf dem Rechner der Kasseninstallation abgelegt, im Beispiel unter C:\GoodCompany\Kasse\sync\
  • Administratorrechte auf diesem Rechner
  • Das Jasypt-Kennwort, mit dem die verschlüsselten Werte in der syncer.properties gelesen werden
  • Bei Betrieb hinter einem Proxy: Adresse und Port des Proxys sowie die Liste der Ziele, die ohne Proxy erreicht werden

Funktionsweise

Der ERPSync ist eine Java-Anwendung und läuft über NSSM als Windows-Dienst. Java übernimmt dabei weder die Proxy-Einstellungen aus dem Windows-Benutzerprofil noch die WinHTTP-Konfiguration. In einem Netz mit Proxy muss der Proxy deshalb ausdrücklich über JVM-Parameter gesetzt werden. Fehlt das, treten typischerweise auf:

  • Connection timed out in der Protokolldatei
  • keine Synchronisation mit der ERP-Cloud
  • keine Lizenz- und Infoabfragen

So gehen Sie vor

  1. Öffnen Sie eine Eingabeaufforderung als Administrator im Verzeichnis des ERPSync.
  2. Registrieren Sie den Dienst. Setzen Sie dabei für <Kennwort> das Jasypt-Kennwort dieser Installation und für <Proxy-Host> und <Proxy-Port> die Werte des Kundennetzes ein:
Batch
%~dp0nssm.exe install ALVARAErpSync "%~dp0open-jdk-17\bin\java.exe" ^
  -jar ^
  -Dspring.config.file=%~dp0syncer.properties ^
  -Djasypt.encryptor.password=<Kennwort> ^
  -Xms128m -Xmx512m ^
  -Dhttp.proxyHost=<Proxy-Host> ^
  -Dhttp.proxyPort=<Proxy-Port> ^
  -Dhttps.proxyHost=<Proxy-Host> ^
  -Dhttps.proxyPort=<Proxy-Port> ^
  -Dhttp.nonProxyHosts="localhost|127.0.0.1|*.local|<weitere Ausnahmen>" ^
  %~dp0erpsync.jar

%~dp0nssm.exe set ALVARAErpSync AppDirectory %~dp0
  1. Ist der Dienst bereits registriert, aktualisieren Sie stattdessen dessen Parameter, sodass dieselben Werte im Feld AppParameters landen.
  2. Starten Sie den Dienst neu, damit Java die Parameter übernimmt:
Batch
nssm restart ALVARAErpSync

Alternativ:

Batch
net stop ALVARAErpSync & net start ALVARAErpSync

Das Jasypt-Kennwort steht in der Dienstkonfiguration und in der Registry im Klartext. Es wird bei der Einrichtung je Installation vergeben — übernehmen Sie kein Kennwort aus einer anderen Installation oder aus einer Dokumentation und geben Sie es nicht an Dritte weiter. Wer es kennt, kann alle verschlüsselten Werte der syncer.properties lesen.

Proxy-Parameter

Parameter Bedeutung
-Dhttp.proxyHost Adresse des Proxys für HTTP
-Dhttp.proxyPort Port des Proxys für HTTP
-Dhttps.proxyHost Adresse des Proxys für HTTPS
-Dhttps.proxyPort Port des Proxys für HTTPS
-Dhttp.nonProxyHosts Ziele, die ohne Proxy erreicht werden. Einträge mit senkrechtem Strich trennen, Platzhalter * ist zulässig

In nonProxyHosts gehören mindestens localhost und 127.0.0.1 sowie die internen Netze und Domänen des Kunden. Ohne diese Ausnahmen leitet Java auch die Verbindung zur lokalen Datenbank über den Proxy.

Port am CentralPoint ändern

Die Lizenzabfrage des CentralPoint läuft über den Dienst ALVARAErpCPSync, standardmäßig auf TCP-Port 8081. Muss ein anderer Port verwendet werden, etwa weil 8081 belegt ist, passen Sie alle drei Stellen an. Fehlt eine davon, lässt sich im CentralPoint keine Lizenz aktivieren.

  1. In der syncer.properties (Verzeichnis C:\GoodCompany\itrCP\sync) den Port setzen, an den sich der Dienst bindet:
    Properties
    server.port=8089
  2. Falls in der CentralPoint-Datenbank vorhanden: die Systemvariable ERPSYNC_CP_URL (Tabelle ipos_systemvariables) auf den neuen Port ändern, z. B. http://localhost:8089/. Darüber verbindet sich die Oberfläche des CentralPoint mit dem Dienst.
  3. Den CentralPoint mit dem Parameter -port starten, z. B. in der Verknüpfung:
    Batch
    "C:\GoodCompany\itrCP\itrCP.exe" -port=8089
    Die Lizenzabfrage läuft beim Start, bevor der CentralPoint mit der Datenbank verbunden ist. Ohne diesen Parameter fragt der CentralPoint den Standardport ab.
  4. Den Dienst ALVARAErpCPSync und den CentralPoint neu starten.

Ergebnis prüfen

  1. Der Dienst ALVARAErpSync läuft in der Dienstverwaltung von Windows.
  2. In spring.log steht kein Connection timed out mehr.
  3. Im Lizenz-Admin-Panel werden die lizenzierten Module angezeigt — der Dienst erreicht die ERP-Cloud also.

Wenn es nicht funktioniert

  • Dienst startet, erreicht die Cloud aber nicht: Prüfen Sie in der Registry unter HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\ALVARAErpSync\Parameters, ob der Wert AppParameters alle Proxy-Parameter enthält. Der Wert ist vom Typ REG_EXPAND_SZ; wird er von der Registrierungsverwaltung als Hex angezeigt, prüfen Sie ihn im Texteditor. Nach jeder Änderung den Dienst neu starten.
  • Anwendung startet gar nicht: Pfade zu syncer.properties und erpsync.jar prüfen sowie das Jasypt-Kennwort.
  • Zeitüberläufe nur bei einzelnen Zielen: Der betroffene Host fehlt in nonProxyHosts oder ist dort zu eng gefasst.
  • Nach einem Portwechsel am CentralPoint lässt sich keine Lizenz aktivieren: Der CentralPoint wird ohne -port oder mit dem alten Port gestartet. Alle drei Stellen aus dem Abschnitt Port am CentralPoint ändern prüfen.
