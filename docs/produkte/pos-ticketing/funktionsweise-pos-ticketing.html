Funktionsweise POS Ticketing

Letzte Änderung 28.10.2026 · Version 7 · Seiten-ID 783

POS Ticketing erzeugt beim Verkauf über die Kasse Eintrittstickets mit eigener Ticketnummer und druckt sie aus — im einfachen Standardformat oder nach einer eigenen Design-Vorlage.

Funktionsweise

Am Artikel wird im CentralPoint ein Ticket hinterlegt. Wird dieser Artikel an der Kasse boniert, fordert die Kasse beim Bonabschluss für jede Position Ticketnummern beim Ticketserver an und druckt die Tickets. Steht auf einer Bonposition die Menge n, entstehen n Tickets.

Der Bon wird wie gewohnt gedruckt, die Tickets je nach Einstellung davor oder danach. Stornorechnungen erzeugen keine Tickets.

Jede vergebene Ticketnummer wird zentral mit Bon, Filiale und Kasse gespeichert und nur einmal vergeben.

Eine elektronische Einlasskontrolle der erzeugten Tickets ist nicht möglich. Der aufgedruckte Code kann derzeit nicht gegen das System geprüft werden.

Beteiligte Komponenten

Komponente Rolle
CentralPoint Tickets anlegen, Ticket am Artikel zuordnen, Verbindung zum Ticketserver pflegen
Ticketserver vergibt die Ticketnummern; Bestandteil des CentralPoint, kein eigenes Programm
ITR Kasse verkauft den Artikel, fordert die Ticketnummern an und druckt die Tickets

Die Verbindung zum Ticketserver (Adresse, Benutzer, Passwort) wird im CentralPoint gepflegt und mit den Stammdaten an die Kassen übertragen.

Voraussetzungen für den Einsatz

  • Eine ITR Kasse und ein CentralPoint. Ohne CentralPoint gibt es keinen Ticketserver; ein Standalone-Betrieb ist damit nicht möglich.
  • Das Professional-Modul Ticketing ist im PartnerPortal für Kasse und CentralPoint freigeschaltet.

Aufbau eines Tickets

Ein Ticket wird im CentralPoint über diese Angaben beschrieben:

Angabe Bedeutung
Name erscheint später in der Auswahl am Artikel
Präambel fester Text vor dem erzeugten Teil der Ticketnummer
Code-Typ Inhalt der Ticketnummer (siehe unten) — nicht das gedruckte Symbol
Generator wie der variable Teil entsteht: fortlaufend (SEQUENCE) oder zufällig (RANDOM)
Generatorlänge Länge des erzeugten Teils
Postambel fester Text nach dem erzeugten Teil
Veranstaltung, PSP Nummer werden für den Export an die Buchhaltung (SAP) verwendet, nicht für die Ticketnummer
Designvorlage Word-Datei im Format *.docx für das Ticketlayout

Aufbau der Ticketnummer

Die Ticketnummer setzt sich zusammen aus Präambel + erzeugtem Teil + Postambel.

Code-Typ Zeichen Generatoren Besonderheit
NUMERIC Ziffern SEQUENCE, RANDOM freie Länge
ALPHANUMERIC Ziffern und Großbuchstaben SEQUENCE, RANDOM freie Länge
GUID 32 Hexadezimalzeichen nur RANDOM feste Länge
EAN8 8 Ziffern SEQUENCE, RANDOM Prüfziffer wird automatisch gebildet, Präambel nur Ziffern, keine Postambel
EAN13 13 Ziffern SEQUENCE, RANDOM Prüfziffer wird automatisch gebildet, Präambel nur Ziffern, keine Postambel
  • SEQUENCE zählt je Präambel fortlaufend. Der Zähler beginnt nach 365 Tagen neu; bereits vergebene Nummern werden dabei übersprungen.
  • RANDOM erzeugt eine Zufallsnummer und benötigt eine Generatorlänge.
  • Präambel und Postambel dürfen nur druckbare ASCII-Zeichen enthalten.

Alternativ können vorab importierte Ticketnummern verwendet werden. Der Artikel erhält dann kein Ticket, sondern ein Schlagwort code_<Typ>; pro Verkauf wird die nächste importierte Nummer dieses Typs vergeben.

Gedrucktes Symbol

Welches Symbol gedruckt wird (QR-Code, Barcode), bestimmt nicht der Code-Typ, sondern:

  • mit Design-Vorlage der Platzhalter in der Vorlage, z. B. {TICKETNUMBER_QR^250},
  • ohne Design-Vorlage die Einstellung Misc.ExhibitionCode.CodeType der Kasse. Das Ticket wird dann im einfachen Standardformat gedruckt: Symbol und, falls eingestellt, die Nummer als Text.

Design-Vorlagen und Platzhalter

Eine Design-Vorlage wird mit Microsoft Word erstellt und als *.docx gespeichert. Text und Bilder werden unverändert übernommen, Platzhalter werden zur Laufzeit durch Werte ersetzt — je nach Format als Text oder als erzeugtes Bild, etwa ein QR-Code.

Ein Platzhalter ist so aufgebaut:

Text
{NAME_FORMAT^PARAMETER}

FORMAT und PARAMETER sind optional. Wird ein Platzhalter-Format erkannt, ist aber unbekannt, erscheint im Ausdruck der Text UNKNOWN. Geschweifte Klammern im Fließtext sind unkritisch, solange sie keinen gültigen Platzhalter bilden.

Verfügbare Platzhalter:

Platzhalter Formatierung Inhalt
{DATETIME} Java SimpleDateFormat Zeitstempel beim Start des Drucks
{ID} Java DecimalFormat Datenbankkennung des Kassenbelegs
{NUMBER} Java DecimalFormat Nummer des Kassenbelegs
{CRCONFIRMEDNAME} Text Name der Kasse, die den Beleg abgeschlossen hat
{CRCONFIRMEDNUMBER} Java DecimalFormat Nummer dieser Kasse
{OPENDATETIME} Java SimpleDateFormat Startzeitpunkt des Belegs
{TOTAL} Java DecimalFormat Gesamtwert des Belegs
{ARTICLENAME} Text Name des Artikels der aktuellen Bonposition
{ARTICLENUMBER} Text Nummer dieses Artikels
{TICKETNUMBER} Text oder Bild-Format Ticketnummer zur Bonposition
{UNKNOWN} Text Ersatz für alle nicht erkannten Platzhalter; nicht selbst verwenden

Bild-Formate für {TICKETNUMBER}: Eine einzelne Zahl hinter ^ gibt eine gleiche Seitenlänge an, mit x getrennt Breite und Höhe. Ohne Größenangabe gilt die Standardgröße.

Format Standardgröße Beispiel
QR 200×200 {TICKETNUMBER_QR^250}
CODE39 200×60 {TICKETNUMBER_CODE39^200x60}
CODE128 200×60 {TICKETNUMBER_CODE128^200x60}
CODE93 200×60 {TICKETNUMBER_CODE93^200x60}
CODABAR 200×60 {TICKETNUMBER_CODABAR^200x60}
ITF 200×60 {TICKETNUMBER_ITF^200x60}
UPCA 200×60 {TICKETNUMBER_UPCA^200x60}
UPCE 200×60 {TICKETNUMBER_UPCE^200x60}
UPCEANEXT 200×60 {TICKETNUMBER_UPCEANEXT^200x60}
RSS14 200×60 {TICKETNUMBER_RSS14^200x60}
RSSEXPANDED 200×60 {TICKETNUMBER_RSSEXPANDED^200x60}
AZTEC 200×200 {TICKETNUMBER_AZTEC^200}
DATAMATRIX 100×100 {TICKETNUMBER_DATAMATRIX^100}
PDF417 200×80 {TICKETNUMBER_PDF417^200x80}

Die Formatnamen werden ohne Unterstrich geschrieben, auch wenn die deutsche Bezeichnung getrennt ist — der Matrix-Code heißt im Platzhalter DATAMATRIX. Die Formate CODE93 bis PDF417 stehen ab Version 5.53 zur Verfügung.

Der Code-Typ des Tickets und das Format des Platzhalters müssen zusammenpassen: Eine alphanumerische Nummer lässt sich nicht als EAN-Barcode drucken.

Zu beachten

  • Format und Größe der Design-Vorlage müssen zum an der Kasse eingestellten Drucker passen. Eine A4-Vorlage auf einem Bondrucker führt zu unbrauchbaren Ausdrucken.
  • Tickets entstehen nur für Bontypen, die dafür freigegeben sind.
  • Die Ticketnummer wird zentral vergeben. Ist der Ticketserver nicht erreichbar, entsteht kein gültiges Ticket.
