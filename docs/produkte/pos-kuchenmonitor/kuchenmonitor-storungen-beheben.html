Küchenmonitor: Störungen beheben

Letzte Änderung 03.11.2026 · Version 7 · Seiten-ID 754

Jeder Abschnitt folgt dem Schema Symptom → Prüfen → Lösung. Mit <IP> ist immer die Adresse des Küchenmonitors gemeint.

Am Monitor kommt gar nichts an

  1. Läuft der Monitor und nimmt er an? Rufen Sie im Browser einer Kasse http://<IP>:2680/customerView auf.
    • Eine Liste in eckigen Klammern (auch leer: []) → der Monitor arbeitet, weiter mit Schritt 2.
    • Ein Fehlertext → siehe Monitor zeigt die Oberfläche, nimmt aber nichts an.
    • Keine Antwort → weiter mit Schritt 3.
  2. Haben die bestellten Artikel ein Ziel? Im CentralPoint unter Kassendaten → Artikel muss am Artikel ein Kimo Ziel Typ gesetzt sein (Küche, Bar oder beides). Artikel ohne Ziel erscheinen nie. Nach einer Änderung die Stammdaten an die Kassen übertragen.
  3. Ist der Monitor von der Kasse aus erreichbar? Auf der Kasse in PowerShell:
    PowerShell
    Test-NetConnection <IP> -Port 2680
    TcpTestSucceeded : False → Monitor aus, falsche Adresse oder Port gesperrt. Das Setup legt die Windows-Firewall-Regeln selbst an. Fehlen sie oder ist eine andere Firewall im Einsatz, auf dem Monitor als Administrator:
    PowerShell
    New-NetFirewallRule -DisplayName "Kuechenmonitor 2680" -Direction Inbound -Protocol TCP -LocalPort 2680 -Action Allow
New-NetFirewallRule -DisplayName "Kuechenmonitor 8086" -Direction Inbound -Protocol TCP -LocalPort 8086 -Action Allow
  4. Kennt die Kasse den Monitor? Der Monitor trägt sich beim Setup-Wizard an der Kasse ein. Wurde der Wizard nicht abgeschlossen oder hat sich die Adresse geändert, durchlaufen Sie ihn am Monitor erneut (siehe Nach einem Adresswechsel kommt nichts mehr an).

Die Kasse wiederholt die Zustellung etwa 10 Minuten lang. Danach verwirft sie die Bestellung; sie erscheint dann nicht mehr am Monitor und muss neu gesendet werden.

Einzelne Artikel fehlen

Symptom: Ein Bon erscheint, aber nur mit einem Teil der Positionen.

Ursache: Bei den fehlenden Artikeln ist kein Kimo Ziel Typ gesetzt.

Lösung: Im CentralPoint unter Kassendaten → Artikel den Kimo Ziel Typ setzen (Küche, Bar oder beides) und die Stammdaten übertragen. Bereits gesendete Bons werden nicht nachträglich ergänzt; neue Bestellungen erscheinen vollständig.

Monitor zeigt die Oberfläche, nimmt aber nichts an

Symptom: Das Programm läuft sichtbar, neue Bestellungen erscheinen nicht. Der Aufruf von http://<IP>:2680/customerView liefert einen Fehlertext statt einer Liste.

Lösung:

  1. Küchenmonitor beenden. Reagiert er nicht, im Task-Manager kimo_flutter.exe beenden.
  2. Über die Verknüpfung auf dem Desktop mit dem angemeldeten Benutzer neu starten.
  3. /customerView erneut aufrufen. Erscheint eine Liste, liefert die Kasse die Bons der letzten 10 Minuten nach. Ältere Bestellungen erneut senden.
  4. Hilft das nicht, den Rechner neu starten. Besteht die Störung danach weiter, wenden Sie sich an den zuständigen Support.

Nach einem Adresswechsel kommt nichts mehr an

Ursache: Die Kasse sendet weiter an die alte Adresse.

Lösung: Den Setup-Wizard am Monitor erneut durchlaufen; die neue Adresse wird an der Kasse eingetragen. Der alte Eintrag bleibt an der Kasse bestehen; die Kasse versucht weiterhin, ihn zu erreichen. Lässt sich die Störung so nicht beheben, wenden Sie sich an den zuständigen Support. Vergeben Sie dem Monitor-Rechner eine feste IP-Adresse, damit das nicht wieder vorkommt.

Auch ein Küchenmonitor, der auf Kundendisplay umgestellt wurde, bleibt an der Kasse eingetragen. Ist an der Kasse kein Küchenmonitor erreichbar, wird keine Abholnummer gedruckt, siehe ITR Partner Service → Produkte → Abholnummer auf dem Kundenbeleg.

Bons bleiben stehen oder stapeln sich

Der Bearbeitungsstatus wird ausschließlich am Küchenmonitor geführt. Bezahlen oder Schließen des Tisches an der Kasse oder in der App entfernt den Bon nicht vom Monitor.

  • Bons am Monitor bis „Am Gast“ abarbeiten.
  • Viele Bons auf einmal: über die Funktion „Angerichtete Positionen auf Abgeholt setzen“.

„Angerichtete Positionen auf Abgeholt setzen“ lässt sich nicht rückgängig machen.

Fehlermeldung beim Start als Küchenmonitor

Port 2680 ist bereits belegt, meist durch eine zweite laufende Instanz. Beenden Sie im Task-Manager alle Prozesse kimo_flutter.exe und starten Sie das Programm einmal neu.

Abholmonitor zeigt ein rotes Ausrufezeichen

Die Verbindung zum Küchenmonitor ist unterbrochen. Prüfen Sie wie oben, ob der Küchenmonitor läuft und vom Abholmonitor aus über die Ports 2680 und 8086 erreichbar ist (Test-NetConnection <IP> -Port 8086).

Ein Antippen des Statussymbols oben rechts — auch wenn es unsichtbar ist — löscht die eingerichteten Küchenmonitore. Der Abholmonitor muss dann neu eingerichtet werden.

Abholmonitor zeigt Kopfzeilen statt Hintergrundbild

Background.png liegt nicht neben kimo_flutter.exe. Legen Sie die Datei dorthin und starten Sie den Abholmonitor neu.

Medienfehler unter Windows 11 Pro N

Das Media Feature Pack nachinstallieren.

Setup bricht ab

  • „Eine aktuellere Version von Kitchen Monitor ist bereits … installiert": Eine ältere Version lässt sich nicht über eine neuere installieren. Deinstallieren Sie zuerst.
  • Fehler 1638 „Eine andere Version des Produkts ist bereits installiert": Ein Setup mit derselben Versionsnummer ist bereits installiert. Deinstallieren Sie zuerst oder verwenden Sie ein neueres Setup.
  • Das Setup läuft ins Leere und es erscheint kein Fenster: Ein abgebrochenes früheres Setup blockiert den Windows Installer. Beenden Sie alle laufenden msiexec-Prozesse und starten Sie das Setup erneut.

Protokolle für den Support

  • Kasse: C:\goodcompany\Kasse\log\spring.log — jede Zustellung an den Küchenmonitor mit Adresse und Ergebnis. Suchbegriff: die Adresse des Monitors.
  • Abholmonitor: Unterordner Log neben der Anwendung.
